# FAST9 — External Audit Attestation v1

التاريخ: 15 نوفمبر 2026.

**الحالة: مكوّن تطويري اصطناعي، NOT_DEPLOYED / GATES_HOLD.**

## ما أضيف
- نقطة تحقق HMAC-SHA256 لرأس سجل Outbox الحالي.
- المفتاح يُمرر من خارج SQLite ولا يُخزّن في قاعدة البيانات أو في كائن النتيجة.
- ربط التوقيع بـ application_id وschema version وkey_id ورقم تسلسل الأحداث وبصمة الرأس وتاريخ إنشاء الإثبات.
- التحقق من توقيع HMAC ومن تطابق الرأس الحالي مع checkpoint خارجي.
- دعم تدوير المفاتيح عبر key IDs؛ إزالة المفتاح القديم من trust map تمنع قبول attestations القديمة.
- رفض المفاتيح القصيرة والمجهولة والتوقيعات والحقول المعدّلة.
- اختبار إعادة بناء سلسلة SHA-256 المحلية بعد تعديل الحدث؛ يظل الفحص المحلي ناجحًا لكن checkpoint الخارجي يرفض الرأس الجديد.
- اختبار انتهاء صلاحية checkpoint عند إضافة حدث جديد، وإصدار checkpoint أحدث.

## طريقة الاستخدام
ينشئ المستدعي checkpoint بمفتاح خارجي، ثم يحفظ كائن `AuditAttestation` في مخزن مستقل محمي (KMS-backed secret service, WORM object store أو سجل مركزي). عند التحقق، يمرر خريطة مفاتيح موثوقة من مصدر خارج قاعدة Outbox.

## حدود الأمان
هذا HMAC checkpoint وليس توقيعًا عامًا؛ كل من يملك المفتاح يستطيع التوقيع. يجب أن يكون المفتاح محفوظًا في KMS/secret manager خارج المضيف والملف، مع صلاحيات كتابة محدودة وتدوير موثق. لا يثبت checkpoint أن الحدث شرعي؛ يثبت فقط أن رأس السجل الحالي يطابق رأسًا سبق ختمه بمفتاح موثوق.

إذا أضيفت أحداث بعد checkpoint يصبح الإثبات القديم غير مطابق للرأس الحالي؛ يجب إصدار checkpoint جديد بعد كل دفعة أحداث أو وفق cadence معلن. لا توجد خدمة KMS أو WORM موصولة في هذه الدفعة.

لا إرسال، ولا مزود هوية حي، ولا نشر أو دمج.
