## الوظائف الجديدة

`apps/fast9_case_source_join/return_handoff.py` يقدّم `read_return_candidate` لعرض حالة التحضير من قراءة موحدة للسجل، و`read_current_evidence` لرفض الحالة غير المكتملة عند فحص حداثة أدلة الحجز. يربط أحدث مسودة بالسؤال والردّ الأخير على الاستيضاح وقراءة المراجع والفحص الفني. يرفض وجود سؤال محذوف، استيضاح معلّق، ملاحظة مفتوحة، نسخة قديمة أو فحص فني لا يخص النسخة الحالية.

بصمة محتوى الجواب هي SHA-256 لتمثيل UTF-8 المدمج للمصفوفة `["human-answer-content.v1", title, body]`، مع `ensure_ascii=False` و`separators=(",", ":")`. تشمل العنوان والنص كما حُفظا. وتبقى مستقلة عن بصمة سلسلة نسخ المسودة وعن بصمة المسودة الثابتة التي يرتبط بها إيصال قراءة السؤال.

صفحة `/review/author/return-preparation/` متاحة لهويتي المؤلف والمراجع المحليتين فقط. تعرض أحدث نسخة، الموانع، مصدر السؤال التدريبي، وروابط التحرير والمراجعة. يستطيع المستخدم معاينة أجزاء النص بعد اختيار حدّ تدريبي والتقسيم صراحةً. لا تغيّر المعاينة السجل، ولا تنشئ محاولة إرسال. لا تُقبل حقول من المتصفح لمنح اعتماد أو تغيير المستلم أو تمرير نسخة أو بصمة بديلة.

عند زوال الموانع تظل الصفحة تعرض: **بانتظار اعتماد المفتي عبر جهة تحقق موثوقة**. لا يصدر هذا المكوّن اعتمادًا ولا ينشئ صلاحية دينية. التحقق الموثوق من هوية المفتي وقراره وإلغائه شرط قائم في `delivery_planner.approval`.

شُغّل الأمران المحددان في `.github/workflows/fast9-integrated-journey.yml` مع Python3.13.5 والاعتمادات المثبتة، على الشيفرة المسجلة في `b20155252c6b5017e1dd42c2011e1fd96ac2c66f`:

| واجهات السؤال والاستيضاح وصاحب السؤال والمؤلف والمراجع والمشغّل والتحضير |28|نجحت كلها|

ضمنها22حالة جديدة:14للربط و8للواجهة. هذه حالات اختبار، وليست أعداد وظائف مكتملة في السكوب. نجح كذلك فحص Ruff للملفات الجديدة وملف المسارات المعدّل، وفحص فروق Git.

تثبت رحلة Django Client، باستخدام جلسات مستقلة وفحص CSRF فعلي، التسلسل: قراءة السؤال ← طلب الاستيضاح ← ردّ صاحب السؤال برمز وحيد الاستخدام ← قراءة الرد ← حفظ المؤلف للمسودة ← التسليم الداخلي ← إتمام المراجع للفحص الفني ← إظهار متطلبات التحضير مكتملة. رُفض تبادل صلاحيات التسليم والفحص بين المؤلف والمراجع.

وتثبت اختبارات الخدمات، باستخدام جهة تحقق **اختبارية فقط**، إنشاء خطة من نص المسودة الفعلي وحفظها وحجزها وإيصالاتها. يظل ACCEPTED في حالة SENT_UNCONFIRMED حتى يصل إيصال DELIVERED موثوق. يرفض الحجز تغيّر السؤال أو نسخة العنوان بعد التحضير، وتبقى محاولة النتيجة المجهولة بحاجة إلى مصالحة دون إعادة إرسال تلقائية. اختبار التسليم يثبت حالة جزء واحد؛ لا يدّعي اكتمال تسليم جميع أجزاء الجواب.

لم تتصل هذه المجموعة بقاعدة PostgreSQL. ملفات SQLite هي سجلات التدريب المحلية القائمة، وليست بديلًا لقاعدة تطبيق الإنتاج.

**فحص المتصفح المحلي تعذّر:** توقف Chromium156.0.8078.79 عبر Playwright1.62.0 قبل إنشاء أي صفحة بسبب `socket() failed: Operation not permitted` وقيود ptrace. لم تُعطّل حماية المتصفح. لا تثبت هذه المحاولة المحلية عرض320/1280 أو التنقل بلوحة المفاتيح.

لمعالجة هذا القيد أُضيف فحص متصفح إلى مهمة GitHub الموحدة، باستخدام أسلوب Chrome المحمي الموجود أصلًا في المستودع. يفحص هويتي المؤلف والمراجع، منع وصول المستخدم غير المسجل والمشغّل، النص الدقيق والتقسيم الصريح، لوحة المفاتيح، عرض320/1280، بقاء السجل دون تغيير ومنع طلبات الصفحة خارج الأصل المحلي. نتيجة التنفيذ الفعلية محفوظة مع طلب المراجعة وفي ملف الأثر `.local/qa/fast9-integrated/return-preparation-browser.json`؛ إضافة الفحص إلى الشيفرة لا تعني نجاحه قبل قراءة هذه النتيجة.

## ملحق إصلاح المراجعة النهائية F1 وF2

**مؤكد محليًا:** نُفّذ الإصلاح على الالتزام `9459eb4df666ea3069de86c1ed228741717569c7`، بشجرة Git `7d4aed5bb6084b0cff1a2565c05c2393d2ba2970`. يضيف هذا الملحق توثيقًا فقط إلى الشيفرة التي اجتازت الفحوص.

- **F1:** كان اختبار دورة التسليم يقطع نص المسودة يدويًا. أصبح يستدعي `parts_for_delivery` باختيار تقسيم صريح، ثم يمرّر الأجزاء المعادة نفسها وقدرات القناة نفسها إلى المخطط. يتحقق من إعادة تركيب النص حرفيًا، وترتيب الأجزاء، وأطوالها المحدودة وبصمات UTF-8. يُشتق عدد محاولات STAGED من الخطة الفعلية. بقيت سجلات القضية والصندوق والحجز والإيصالات والمصالحة حقيقية داخل الاختبار، وجهتا التحقق من الاعتماد والإيصال اختباريتين فقط.
- **F2:** أُعيد إنتاج الرفض الخاطئ للكلمة التي يساوي طولها الحد، مثل `كلمة أو` عند حد 4. أظهر التشغيل الأحمر 8 اختبارات مع 4 أخطاء في الحالات الفرعية المتوقعة، كلها `unbreakable_token_requires_human_edit`. يسمح الإصلاح بحدّ آمن قبل المسافة عند غياب حدّ صالح بعدها، مع إبقاء تفضيل الحدود السابقة وحماية التشكيل وCRLF وZWJ وعدم حذف أي محرف. تغطي 3 حالات اختبار جديدة الكلمة الأولى والداخلية وCRLF والتشكيل وتفضيل الحدود ورفض الكلمة الأطول أو الحد غير الآمن. بقي شرط الاختيار الصريح وحد 16 جزءًا قائمين.

## فحص GitHub وإصلاح سياسة نماذج المكتب المحلي

حُفظت الدفعة في [طلب المراجعة المسودة #194](https://github.com/sami77337/fatwa-platform/pull/194)، فوق PR193، مع إبقاء تاريخَي PR184 وPR189. شجرة النشر الأولى `ff0d9767293963a6c2342c7a6c25cd375ca3e3cb` تطابق الشجرة المحلية حرفيًا؛ التزام GitHub الأول `7bba747eefab220b4f50b0b2bc53b22a47be070d`.

في [التشغيل المستضاف الأول](https://github.com/sami77337/fatwa-platform/actions/runs/43701916314) نجحت **80 + 28 = 108 اختبارات** على نسخة الدمج `a013a269c53345df4c60c08a2bdf68d2529380f4`. بدأ Chrome الفعلي، ثم أخفق فحص المتصفح عند دخول المؤلف. نجحت التشغيلات السبعة عشر الأخرى للفرع وطلب المراجعة، بما فيها B6 وC6 وD6. هذه تشغيلات متداخلة، وليست وظائف جديدة أو نسبة إنجاز.

كشف التحقيق أن ملف المكتب المحلي يرث `Referrer-Policy: no-referrer`. يحدد [معيار Fetch](https://fetch.spec.whatwg.org/#append-a-request-origin-header) أثر هذه السياسة على Origin لطلبات النماذج، ويتحقق [Django](https://docs.djangoproject.com/en/5.2/ref/csrf/) من الأصل المرسل ضمن حماية CSRF. **الآلية والإعداد مؤكدان، لكن السبب المباشر للطلب الأول مرجّح** لأن أثره لم يسجل حالة POST أو أصله.

يضبط الإصلاح `3a58ae887baddb5249942cb3be5a5d70979a7d26` السياسة على `same-origin` في ملف إعدادات المكتب المحلي فقط. تبقى سياسة الصفحات العامة، وفحص CSRF، وقائمة الأصول الموثوقة، وقيود ملفات الارتباط والصلاحيات كما هي. يلتقط فحص المتصفح الآن حالة POST الأصلية وتصنيف Origin ونجاح إعادة التوجيه، دون رموز دخول أو ملفات ارتباط أو نصوص طلبات.

**التحقق المحلي المركّز بعد الإصلاح:** نجحت 12 حالة: 8 حالات التحضير السابقة، و3 حالات جديدة لسياسة النموذج وحدود CSRF، وحالة سياسة الصفحات العامة. تشمل الحالات الجديدة دخول الأدوار الثلاثة من الأصل نفسه، و9 حالات فرعية لرفض الأصل الفارغ/الأجنبي/منفذ محلي آخر، و6 حالات فرعية لرفض رمز CSRF المفقود أو الخاطئ. نجحت الحالات الثلاث الجديدة أيضًا عند تشغيلها بملف إعدادات المكتب الفعلي. لا تُجمع إعادة التشغيل أو الحالات الفرعية بوصفها اختبارات مستقلة جديدة. صار عدد الاختبارات الذي سيكتشفه الأمران الموحّدان 111 بدل 108؛ نتيجة تشغيلها المستضاف بعد الإصلاح تؤخذ من طلب المراجعة وأثر المتصفح، ولا تُستنتج من إضافة الاختبارات.

1. وصل جهة هوية واعتماد موثوقة للمفتي بعقد الإيصال القائم، مع التحقق من الصلاحية والإلغاء والنسخة الدقيقة. لا يجوز تحويل إتمام الفحص الفني إلى هذا الاعتماد.
