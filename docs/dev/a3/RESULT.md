## السلوك المنفذ

- يعرض / صفحة رئيسية عربية مستقلة بدل إعادة عرض الفهرس نفسه، مع تنقل إلى /help والفهرس الحقيقي.
- يرسل البحث طلب GET إلى /fiqh مع q وbasic=1. تظل قواعد التحقق والبحث الحالية في تطبيق reference مسؤولة عن معالجة الطلب.
- روابط التصفح تستخدم /fiqh?basic=1 للاستفادة من العرض الخادمي القائم دون JavaScript.
- تقرأ الرئيسية ملخص المصدر فقط عبر خدمة list_books(Page(1)) القائمة؛ هذه قراءة ORM محدودة بالعدد ومصدر واحد، دون استعلام العناوين.
- عند مصدر واحد، يظهر عنوان العمل الأصلي من البيانات، مع البحث. لا تعرض الصفحة إحصاءات ثابتة أو عناوين اصطناعية.
- عند غياب المصادر، تظهر رسالة واضحة ورابط الدليل والتصفح. عند تعذر القراءة، تبقى الرئيسية متاحة برسالة عامة دون كشف تفاصيل الخطأ. نجاح الرئيسية في هذه الحالة لا يعني جاهزية قاعدة البيانات؛ /readyz باقٍ كما هو.
- عند تعدد المصادر لا تختار الرئيسية مصدرًا ضمنيًا ولا تعرض محدد طبعة، وتحيل إلى صفحة الفهرس.
- يقدم /help شرحًا للتصفح والبحث وقراءة الجزء والصفحة المطبوعة ومسار العنوان، ويوضح أن المصدر المقصود هو فهرس كشاف القناع، طبعة وزارة العدل، وأنه ليس فتاوى منشورة أو تصنيفًا عامًا للفتاوى. لا يحتاج الدليل إلى قراءة قاعدة البيانات.
- الصفحتان RTL، بقالب HTML خادمي، وعناوين ومعالم دلالية، وروابط عادية، ورابط لتجاوز التنقل، وتحديد الصفحة الحالية، وتسميات لحقل البحث.
- يعاد استخدام reference/style.css دون تعديله. لا JavaScript أو CSS مضمن أو موارد خارجية في الصفحتين.
- تقتصر الدالتان على GET وHEAD عبر require_safe. يظل PublicReadOnlyMiddleware وقائمة MIDDLEWARE وCSP كما هي، ويستمر رفض بقية الطرق قبل تنفيذ قراءة الفهرس.
- لا تغيير في /fiqh أو /healthz أو /readyz أو مسارات API أو معالجاتها أو نموذج البيانات أو الترحيلات.

قوالب reference خارج ملكية A3. محدد الطبعة القديم الموجود فيها لم يعدل؛ إزالته من صفحة /fiqh تتبع مسار الفهرس في العمل المتوازي. الصفحتان الجديدتان لا تعرضان محدد طبعة أو معلمات مصدر تقنية.
