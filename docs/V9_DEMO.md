# تشغيل V9 التجريبي المحلي

هذا المشغّل يتيح واجهات V9 الحالية فوق قاعدة PostgreSQL اصطناعية معزولة. يعيد
استخدام مشغّل V8 وملف `config.settings.campaign_review`، بما فيه هويتا التجربة
ومواضع المرجع وملفات الوسائط. لا يغيّر إعدادات التطبيق الافتراضية.

**Gate B NOT_PASSED — C/D/E HOLD — Phase01 BLOCKED — NOT_DEPLOYED.**
لا بيانات حقيقية أو حسابات إنتاج، ولا إرسال خارجي أو اعتماد شرعي آلي.

## التشغيل

من جذر المستودع، باستخدام Python 3.13 والمتطلبات المثبتة وPostgreSQL 17:

```sh
python infra/dev/with_casework_postgres.py \
  --pg-bin /path/to/postgresql/17/bin --major 17 \
  --settings config.settings.campaign_review -- \
  python -m infra.dev.v9_demo
```

في بيئة التطوير الحالية:

```sh
/workspace/fatwa-platform/.local/venv/bin/python infra/dev/with_casework_postgres.py \
  --pg-bin /workspace/fatwa-platform/.local/runtime/pg17/usr/lib/postgresql/17/bin \
  --major 17 --settings config.settings.campaign_review -- \
  /workspace/fatwa-platform/.local/venv/bin/python -m infra.dev.v9_demo
```

يفتح الخادم على `http://127.0.0.1:8018` فقط. يعرض الطرفية:

- رمز وصول سري اصطناعي لقضية واحدة، ومرجع القضية.
- اعتماد دخول عشوائي لكل من `demo-mufti` و`demo-publisher`، لمدة 45 دقيقة.
- مسار ملفات التجربة `.local/qa/v8/samples/`، ومسار التخزين الخاص المؤقت.

الاعتمادات عشوائية لكل تشغيل؛ لا توجد كلمة مرور ثابتة في الشيفرة. مرجع القضية
FT لا يكفي لتسجيل الدخول. الهويتان مخولتان فقط لهذه القضية المزروعة؛ إدخال
قضايا أخرى لا يوسع نطاقهما تلقائيًا. أوقف التشغيل بـCtrl+C؛ تُزال قاعدة التجربة
ودليل الأصول الخاص المؤقت. تبقى ملفات العينات الاصطناعية الموروثة في `.local/qa`.
ليس هذا المشغّل إعداد تخزين دائم للإنتاج أو تجربة نسخ احتياطي.

## رحلة قابلة للتجربة

1. افتح سياق متصفح للسائل على `/casework/status/` وأدخل رمز الوصول المطبوع.
   القضية منشأة فعلًا عبر `source_case_intake` من حدث موقع اصطناعي، مع حفظ
   JSON الأصلي وبصمته وربطه بأول إصدار وقائع؛ لا توجد قضية ثانية موازية.
2. ارفع صورة وPDF وWAV من العينات. كل رفع ينشئ إصدار وقائع جديدًا، ويحفظ
   الأصل في ملفات خاصة immutable خلف صلاحية القضية، مع بقاء المرجع والبصمة
   في PostgreSQL. لا يوجد رابط static/public للملف.
3. في سياق متصفح مستقل، افتح `/casework/staff/login/` وسجل الدخول باعتماد
   `demo-mufti`. افتح القضية: يظهر أصل الرسالة ومعرّف المصدر والمحادثة
   والبصمة والنص الأصلي. عاين المرفقات وشغّل الصوت. يمكن طلب استيضاح ثم الرد
   عليه من سياق السائل.
4. افتح محرر الإحالات، وابحث عن `تجريبي`. اختر المواضع الموجودة من الطبعة
   الاصطناعية، واكتب نصًا بشريًا تجريبيًا واحفظ الإحالات. هذه عناوين ومواضع
   مرجعية مختلقة معلّمة للتجربة، وليست نصوص كتب كاملة أو تخريجًا علميًا حقيقيًا.
5. افتح محرر أجزاء الجواب وأضف PDF، ثم احتفظ به وأضف WAV في إصدار لاحق.
   راجع النص والملفات والإحالات، واعتمد الإصدار الحالي يدويًا كمفتي. لا ينشئ
   المشغّل جوابًا أو قرار اعتماد. بعد ذلك أكّد الإتاحة الخاصة بإجراء منفصل؛
   يظهر للسائل مدخل الجواب المركب. هذه إتاحة خاصة وليست إثبات توصيل أو قراءة.
6. افتح تجهيز توصيل الجواب المركب، وصدّر طلب خطة الأجزاء. الوجهة مرتبطة
   بأصل القضية، وقدرات القناة هنا تعريف اصطناعي لمحاكٍ محلي. استيراد إذن
   موقّع يتطلب مفتاح تحقق عام اختياري كما أدناه؛ لا يوجد مرسل أو عامل إرسال.
7. أنشئ نسخة تحريرية مرشحة للنشر، وراجع إزالة البيانات الشخصية. ادخل في سياق
   مستقل باعتماد `demo-publisher` لمنح موافقة نشر مستقلة. بعد الموافقة فقط
   تظهر النسخة في المكتبة التجريبية المغلقة.
8. افتح المواد المرتبطة من المنشور. يقترح `demo-mufti` علاقة بموضع مرجعي
   موجود في إحالات المنشور، ويعاينها. يوافق `demo-publisher` عليها بإجراء
   مستقل، فتظهر في البحث والفتح المصرح. يمكن تصحيح العلاقة أو سحبها.
   لا يزرع المشغّل تفريغ درس ولا يمنح `OPEN_TRANSCRIPT`؛ هذا المسار يبقى مغلقًا.

تعديل الوقائع أو الجواب أو الإحالات يستلزم اعتمادًا وإتاحة جديدين بحسب قواعد
الإصدار الحالية. تغييرات التخزين الفيزيائي لا تمنح اعتمادًا. خدمة تحويل التخزين
الإدارية تبقى مغلقة في هذا العرض، ولا توجد واجهة إدارية أو صلاحيات منظم مستحدثة.

## تسليم طلب التوقيع إلى جهة مستقلة

بلا خيار إضافي يمكن تصدير طلب تجهيز الأجزاء، لكن تسجيل خطة موقعة مغلق.
لتجربة التحقق من إذن **اصطناعي** صادر عن جهة مستقلة، ابدأ جلسة جديدة مع:

```sh
python infra/dev/with_casework_postgres.py \
  --pg-bin /path/to/postgresql/17/bin --major 17 \
  --settings config.settings.campaign_review -- \
  python -m infra.dev.v9_demo \
    --approval-public-key /private/synthetic-authority.pub \
    --provider-public-key /private/synthetic-provider.pub
```

يجب توفير المفتاحين معًا؛ وإلا يبقى العرض في وضع تصدير الطلب فقط.
كل ملف يحتوي مفتاح Ed25519 **عامًا خامًا، 32 بايت** فقط، لا PEM ولا مفتاحًا خاصًا.
المشغّل لا ينشئ مفتاح توقيع ولا يوقع نيابة عن المستخدم. جهة التوقيع المستقلة
غير مرفقة بهذا العرض، ويجب أن يراجع الإنسان الطلب كاملًا قبل إصدار الإذن.
إعداد التحقق ثابت لهذه التجربة:

| الحقل | القيمة |
|---|---|
| issuer | `synthetic-v9-offline-authority` |
| audience | `synthetic-v9-composite` |
| key_id | `demo-public-key` |
| approver_id | `demo-mufti` |
| approver_role | `MUFTI` |
| decision | `APPROVE_RETURN_TO_ORIGIN` |

تُنسخ هوية الوقائع والإصدار وبصمات الطلب من ملف الخطة الحالي بالضبط. تنسيق
الإيصال هو `SignedApprovalReceipt` وتوقيعه على `approval_signing_payload` في
`apps.delivery_planner.trusted_identity`. يحتوي رد الاستيراد على `receipt` و
`request_sha256`؛ في مسار الجواب المركب تساوي الأخيرة `plan_sha256` المصدر.
يلزم nonce فريد وعمر قصير ضمن حدود المحقق الحالي. تعيد خدمة الطابور التحقق
من الإذن والاعتماد والهوية والإصدار، وتمنع إعادة استخدام الإذن لخطة مختلفة.
لمحقق إيصالات الموفر العام: `issuer=synthetic-v9-offline-provider`،
`audience=synthetic-v9-provider-events`، `key_id=demo-provider-key`،
`provider=composite-simulator`. وجود هذا المحقق مطلوب قبل تسجيل الخطة؛
ولا ينشئ توقيعًا أو إيصالًا أو حدث موفر.
لا توجد إدارة إلغاء مفاتيح مستقلة في هذا العرض المؤقت؛ إيقاف العملية ينهي الثقة.

حتى بعد تسجيل الخطة الموقعة لا يبدأ أي إرسال، ولا تُولد إيصالات موفر أو
أحداث «تم التوصيل». لا يفعّل هذا العرض موصل Telegram أو YouTube أو WhatsApp.

## فحص تشغيل مركز

أضف `--smoke` إلى الأمر. ينفذ الفحص تشغيلًا قصيرًا ثم يخرج، دون إبقاء خادم:

```sh
python infra/dev/with_casework_postgres.py \
  --pg-bin /path/to/postgresql/17/bin --major 17 \
  --settings config.settings.campaign_review -- \
  python -m infra.dev.v9_demo --smoke
```

يتحقق من قضية مصدر واحدة وحفظ payload حرفيًا، وموضعَي المرجع الموروثين،
وجلسات سائل ومفتي فعلية عبر Django HTTP مع CSRF، وعرض أصل الرسالة، ورفع
ملف اصطناعي عبر الخدمة إلى التخزين الخاص وقراءته بالمفتي ببصمة مطابقة.
يتحقق أيضًا من عدم إنشاء جواب أو اعتماد أو DeliveryIntent. يطبع ملخص JSON
بلا رموز وصول أو اعتمادات. هذا فحص بدء تشغيل، وليس بديلًا عن رحلة متصفح V9
الكاملة أو دليل اعتماد وظيفي شامل.

التحقق المحلي المنفذ: نجح `--smoke` على PostgreSQL 17.12، ثم نجح مع تهيئة
مفتاحَي تحقق عامين اصطناعيين؛ لم تُنشأ توقيعات أو قرارات اعتماد. نجح كذلك بدء
الخادم الفعلي على loopback والحصول على HTTP 200، ثم إيقافه وإزالة دليل التخزين
المؤقت. نجح Ruff وformat وdiff whitespace. لم يُعد تشغيل مجموعة اختبارات V9
الكاملة، ولم تُنفذ في هذا المسار تجربة توقيع خارجي أو موافقة نشر أو متصفح كاملة.
