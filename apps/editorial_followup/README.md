## التشغيل

باستخدام Python 3.13 وتبعيات المشروع المثبتة:

```powershell
python -m apps.editorial_followup
```

افتح <http://127.0.0.1:8016/dev/editorial-followup>.
يتجاوز المشغّل فحص الترحيلات القبلي فقط لأن العرض يستعمل العينات الثابتة في الذاكرة؛
تبقى حواجز Django للإنتاج واسم المضيف والاتصال المحلي وطرق HTTP فعالة.
لا يتطلب هذا المسار قاعدة بيانات ولا ينشئ ترحيلات.

## الوقائع المعروضة

- تصحيح أو استكمال المدخل: رفض الاستلام، أو غياب رابط المقطع، أو تشخيص خطأ
  بنيوي/حقل غير مرجعي. طلب مطابقة مرجعية وحده ليس خطأ في المدخل.
- غياب مؤشرات إحالة قابلة للعرض: قد تكون غير مرفقة أو ذات بنية مرفوضة؛ لا يُفترض
  غياب المصدر من الجرد أو الواقع.
- الإحالات غير المتحققة تقنيًا: تحافظ على حالة الخدمة ورمز السبب وموضع المؤشر،
  بما يشمل الالتباس والتعارض. الروابط تفتح السجل والمؤشر نفسيهما.
- الصفوف المرفوضة وإيصالات المسودات غير المتاحة: مستقلان عن تحقق المراجع؛
  غياب المسودة يعني `record is None` في الخدمة الحالية فقط.
- إرشادات تجهيز الفحص مشتقة من الأسباب؛ تستخدم `recovery_ar` الحالي عند توفر
  رموز تشخيص منظمة، ولا تُسنِد مستخدمًا أو مهلة أو قرارًا تحريريًا.

تعرض القائمة السجلات ذات سبب متابعة واحد على الأقل، مرة واحدة لكل هوية ثابتة.
السبب والدفعة وحالة الاستلام تُرشّح معًا. ترتيب الخدمة ثابت؛ السابق والتالي أقرب
سجلين مطابقين دون التفاف. روابط التفاصيل المباشرة خارج التصفية تبقى قابلة للفحص
مع تنبيه ودون جيران. لا يُستخدم المعرّف الخارجي المتكرر للربط.

تعذر تحليل دفعة يظهر منفصلًا ويتبع مرشح الدفعة فقط، دون اختلاق صف أو مسودة.
التفاصيل تحفظ النص العربي والتشكيل والمسافات وCR/LF، وبصمة المدخل وبصمة تمثيل
الصف وحدود شريحة UTF-8 حيث كانت متاحة. تمثيل صفوف CSV/JSON المحللة موسوم
بوضوح بأنه تسلسل حقول، وليس البايتات الأصلية. تشخيص `history` يخص أحدث لقطة
ثابتة، بينما تشخيص بقية السجلات يخص الاستلام الأصلي.
