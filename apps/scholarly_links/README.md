# الدروس والعلاقات اليدوية — وحدة وظيفية تجريبية مغلقة

هذه الوحدة تنفذ تنظيم سلاسل ودروس فعلية وربط نسخ أجوبة القضايا بها، وعلاقات بشرية محددة بين قضيتين. تحفظ معرفات مستقرة وإصدارات ومصادر وتاريخ قرار مستقلًا. لا تصدر حكمًا، ولا تدمج قضايا أو هويات، ولا تغير جوابًا أو اعتماده أو وقائعه، ولا تنشر مادة تلقائيًا.

التشغيل مقصور على قاعدة PostgreSQL الاصطناعية المملوكة، و`FATWA_PRODUCTION=0`. تبقى Gates HOLD، ولا يفيد وجود الوظيفة قبول سياسات U03 أو صلاحية تشغيل إنتاجي.

## ما يعمل

- إنشاء تصنيف مستقل للدروس في `LessonCategory`؛ لا يوجد ربط ضمني بينه وبين Sharia Taxonomy أو وسوم السؤال.
- إنشاء سلسلة بعنوان ومعلم واحد أو أكثر، ثم دروس داخلها بمعرفات مستقرة منفصلة عن ترتيبها.
- إعادة ترتيب الدروس، وتعديل عنوان السلسلة ونسبة معلميها، وحفظ نسخة جديدة من الدرس دون طمس النسخ أو كسر الروابط القديمة.
- حفظ مرجع إدخال بشري. يمكن اختيار ملف أصلي محفوظ من أجزاء جواب موجود في قضية السلسلة، أو إبقاء سجل وصفي بلا ملف رقمي. لا يفترض النظام تفريغًا أو ملفًا غير موجود.
- تثبيت ملف المصدر بمعرف الجزء، ومعرف الجواب ونسخته ونسخة الوقائع، وبصمتي الملف وحزمة الأجزاء. تحويل التخزين الفيزيائي لا يعيد توجيه هذا الربط إلى مادة أخرى.
- ربط الجواب بأكثر من درس، مع اختيار النسخة المقصودة وموضع زمني اختياري مثبت على تسجيلها. الأرقام الحالية في النموذج بالمللي ثانية، وتتحقق من مدة الملف الموثقة؛ لا تخمّن موضعًا.
- إنشاء علاقات `RELATED` و`REFERRED_BY_SHEIKH` و`DUPLICATE_OF` و`SUPERSEDES` باتجاه محفوظ بين قضيتين وجوابين محددين. الهدف جواب سبق أن اعتمده إنسان؛ لا يكتفى بعنوان أو نص إحالة حر.
- إبقاء الاقتراح منفصلًا عن الاعتماد أو الرفض، وسحب علاقة معتمدة مع تاريخها. تظهر الإحالة الواردة بعبارة مناسبة دون قلب اتجاهها العلمي.
- بحث نصي في نطاق القضايا المصرح بها، مع مرشحات اختيارية للسلسلة والدرس وتصنيف الدرس ونوع العلاقة والطرف الآخر. تدخل الروابط المعتمدة فقط في المرشحات؛ يبقى النص غير المنظم قابلًا للعثور عليه. تبقى روابط النسخ التاريخية قابلة للبحث إذا حجبت نسخة درس أحدث.
- نماذج HTML أصلية متصلة بالقضية، مع CSRF وأشكال حقول دقيقة، وصفحة تاريخ نسخ الدرس وفتح الملف الأصلي بعد تحقق مستقل من إذن الوسائط.

## السلطة والنسبة والخصوصية

`FATWA_SCHOLARLY_LINKS_ENABLED=False` و`FATWA_SCHOLARLY_LINKS_AUTHORITY=None` هما الافتراضيان. تشغيل العلم وحده لا يكفي: `ScholarlyAuthority` يحتاج منحًا صريحة للأفعال `MANAGE_LESSONS`, `READ_LESSON`, `READ_MEDIA`, `READ_LINK`, `PROPOSE`, `APPROVE`, `REJECT`, `WITHDRAW`. إذن قراءة رابط أو اقتراحه لا يمنح اعتماد علاقة حساسة.

يعاد حل هوية MUFTI الحالية ونطاقها عند البداية والنهاية. يلزم نطاق القضية الأصلية والطرف الآخر أو قضية مصدر الدرس معًا. لا يحصل ORGANIZER على صلاحيات جديدة، ولا يتحول تكليف أو علاقة إلى تفويض وصول. `projection_epoch()` قراءة ذرية بلا آثار جانبية، تتغير مع كل تعديل لمنح المستخدم أو الفعل أو المورد أو الطرفين.

أسماء المعلمين مدخلة صراحة. يمكن ربط نسبة معلّم بمفتاح هوية موثوق اختير صراحة وتحقق نشاطه ونطاقه وقت الحفظ؛ لا يطابق النظام أسماء الأشخاص لاستنتاج الهوية. الواجهة تسمح للمفتي أن ينسب الاسم الأول إلى حسابه صراحة؛ الأسماء التاريخية أو غير المسجلة تبقى دون مفتاح حساب. أسماء الحسابات ومفاتيحها لا تتحول إلى عناوين عامة.

الفئات والسلاسل والدروس والروابط بيانات داخلية. لا تمنح `READ_LESSON` إذن `READ_MEDIA` أو أي نشر/تصدير/قراءة مجهولة. توفر `LessonSeries.public_id` و`Lesson.public_id` معرفات عامة عشوائية منفصلة عن الهوية الداخلية؛ استعمالها العام مشروط بوحدة النشر ومنحها المستقلة.

## سلامة الإصدارات والتزامن

الثماني جداول الجديدة تحفظ هويات غير قابلة للتغيير أو صفوفًا مسلسلة مختومة. يحسب Python تمثيلًا قانونيًا كاملًا للصف؛ يتحقق PostgreSQL من مطابقته لكل أعمدته ومن SHA-256، ثم يثبت وقت المعاملة ومعرفها. ترفض المشغلات UPDATE وDELETE. يشترط قيد مؤجل وجود نسخة أولى لكل هوية سلسلة أو درس.

تتحقق المشغلات من ترتيب الإصدارات، وسلسلة البصمات، وانتماء المصدر إلى قضية السلسلة، ومعرفات الأجوبة وبصماتها، وحدود التوقيت، والحالة الصحيحة للقرار. يمنع تكرار علاقة حية بنفس الطرفين والإصدارات والنوع، وتمنع دورات `DUPLICATE_OF` و`SUPERSEDES`. يتطابق ترتيب قفل الرسم البياني والقضايا بين الخدمات وSQL؛ تختبر المنافسة الفعلية قرارين متعاكسين مع تعطيل فحص Python لإثبات منع الدورة في قاعدة البيانات نفسها.

تستخدم الأوامر UUID لإعادة الطلب المطابق دون تكرار السجل. يتعارض تغيير المقصود بنفس المفتاح، أو نسخة قضية/طرف/سلسلة/درس قديمة. لا ترفع هذه العمليات `EvidenceVersion` ولا تعدل `CaseEvent` أو جواب الشيخ.

النطاق الحالي محدود صراحة: حتى 32 سلسلة و64 تصنيفًا لكل قضية، و64 درسًا داخل السلسلة، و128 نسخة للسلسلة أو الدرس، و128 علاقة من كل نوع سجل لكل قضية. هذه حدود تطوير معلنة وليست قرار أحجام الإنتاج.

## حد تركيب الصفحة

يبقى قفل القضايا داخل `synthetic_queue_atomic()` حتى انتهاء نماذج الويب وcontext processors وعرض القالب. يبدأ طلب الويب بقفل الرسم البياني قبل أي قفل قضية، وتحدد خدمة القراءة القضايا وتقفلها بترتيب UUID. تعاد مراجعة هوية القارئ، وكائن السلطة وإصداره، ومنح الموارد، والملفات الفعلية قبل تسليم الاستجابة. يثبت `projection_fingerprint(case_ids)` مؤشرات القضية وكل الهويات والإصدارات والروابط وقراراتها، بما فيها المجموعات الفارغة؛ تلتقط البصمة قبل قراءات العرض واستدعاءات الإذن، وتكشف المقارنة قرار سحب جديدًا أو تغيير بيانات أو وقائع أثناء العرض. الأوامر تحصل على بصمة قراءة مستقلة بعد اكتمال التغيير المصرح به. لا تكفي إعادة فحص الهوية وحدها، ولا إعادة تثبيت البصمة بعد تكوين النتائج.

اختبارات الويب تتسبب عمدًا في سحب علاقة، وإضافة تعقيب، وتغيير نسخة سلسلة داخل عملية عرض القالب؛ ترفض الصفحة كاملة ويرجع تغيير التركيب المحلي، بدل تسليم بطاقة أو عدد قديم. يثبت اختبار آخر رفض النتائج والعدد عند سحب حقيقي داخل إذن `READ_LINK` بعد قراءة حالة الرابط وقبل تكوين آخر نتيجة. ويثبت اختبار بمعاملتين متنافستين أن نموذج العلاقة لا يحتجز قضايا أثناء انتظاره قفل الرسم البياني الذي تملكه معاملة أخرى.

## التكامل الذي يملكه المنسق

1. أضف `apps.scholarly_links` إلى التطبيقات مع العلم والسلطة المغلقين أعلاه. إعدادات الوحدة تستخدم إزالة التكرار، فتتحمل تسجيلها في `campaign_review`.
2. أضف `apps.scholarly_links.context.scholarly_links` إلى context processors.
3. مرر `apps.scholarly_links.views.ACTIONS` إلى `workspace`. كل الأفعال POST أصلية على `/casework/staff/`؛ لا يلزم مسار خاص جديد.
4. أدرج `scholarly_links/entry.html` و`scholarly_links/research_entry.html` مع `scholarly_case_ref`. في الفرع المدمج تمت إضافتهما إلى قوالب القضية والبحث المشتركة؛ الإعداد الاختياري يعيد استخدامها دون تطبيق overlays إضافية تكرر النماذج.
5. محول البحث `apps.research_workspace.scholarly_adapter.search` يعيد المرشحات الفعلية والنتائج المصرح بها. لا يغير محرك استرجاع النصوص أو أوزانه.

الأفعال: `scholarly_open`, `scholarly_search_open`, `scholarly_search`, `lesson_category_create`, `lesson_series_save`, `lesson_save`, `lesson_move`, `lesson_view`, `lesson_media`, `relation_propose`, `lesson_link_propose`, `scholarly_review`.

### عقد المعاينة العامة

`services.approved_candidates_for_locked_case(case=..., answer_id=...)` محول **داخلي**، يشترط معاملة قاعدة بيانات. يعيد روابط معتمدة للجواب المحدد فقط بعد التحقق من السجل والمصدر. يعيد معرفات الأطراف والإصدارات والبصمات ومفاتيح نسبة المعلمين داخل Python، ولا يعيد النصوص أو عناوين الدروس الأصلية أو ملاحظات المراجعة.

على محول المعاينة العامة حصر كل الأطراف وقضايا مصادر الدروس، وقفلها بترتيب UUID، والتحقق من النطاق الحالي ومنح `READ_LINK` و`READ_LESSON`، ومنحي Publication دقيقين لطرفي العلاقة، ومنح نشر مؤقت صريح لمحتوى درس منقح مستقل. يجب تثبيت السلطة والبصمات عبر كامل عرض HTML/XML وإعادة التحقق من المصادر عند النهاية. هذه الدالة لا تمنح أي إذن عام. يملك مسار `public_knowledge` ذلك التكامل؛ لا تثبت هذه الوحدة وحدها اكتمال نشر الدروس للعامة.

## مخزون الاستعادة

الجداول:

```text
scholarly_links_lessoncategory
scholarly_links_lessonseries
scholarly_links_seriesversion
scholarly_links_lesson
scholarly_links_lessonversion
scholarly_links_caserelation
scholarly_links_caselessonlink
scholarly_links_linkdecision
```

كل المفاتيح UUID؛ لا توجد sequences جديدة. الدوال هي `sl_identity_guard()`, `sl_identity_complete()`, `sl_sealed_guard()`. أسماء المشغلات العشرة مصدّرة في `recovery_support.TRIGGERS`، والجداول والدوال في `TABLES` و`FUNCTIONS`.

`recovery_support.populate()` يملأ كل جدول بخدمات حقيقية ومواد اصطناعية، ويعيد JSON pins لا تتضمن بيانات اعتماد أو سياسة قابلة للتسلسل. `verify_restored(pins)` يعيد بناء سلطة اصطناعية في العملية الحالية، ويتحقق من سجلات الاعتماد والهوية العامة والإصدار والموضع وبايتات الأصل وكل البصمات المسجلة. نجاح تحقق داخلي في قاعدة الاختبار لا يعادل نجاح تمرين النسخ المشفر وإعادة التشغيل؛ يملكه المنسق ويجب تسجيل دليله المستقل.

## التحقق

اجتازت المجموعة المحلية 45 اختبارًا متميزًا على PostgreSQL 17.11 و18.7 في 2026-11-20، بما فيها خدمات وقيود SQL وتنافس فعلي وHTTP أصلي وتركيب الصفحة والاستعادة الوظيفية واستبدال السلطة أثناء آخر استدعاء إذن. نجاح الاختبارات نفسها على محركين ليس 90 اختبارًا متميزًا. مرّ Ruff وفحص عدم وجود migrations ناقصة. محاولة المتصفح المحلي توقفت عند بدء Chromium المحمي بخطأ `socket() failed: Operation not permitted` قبل الوصول إلى التطبيق؛ لا يوجد PASS محلي للمتصفح، ويلزم تشغيل الصف على CI المحمي لدى المنسق. تمرين الاستعادة المشفر والمتصفح المتكامل يبقيان دليلين منفصلين عن هذه المجموعة.

تشغل المجموعة عبر `apps.scholarly_links.settings`:

```bash
python manage.py test apps.scholarly_links.tests --noinput
python manage.py test apps.scholarly_links.browser_tests --noinput
```

يلزم PostgreSQL 17 أو 18 مملوك اصطناعيًا؛ يوفر `infra/dev/with_casework_postgres.py` القاعدة المؤقتة. لا تستبدلها SQLite. اختبار المتصفح يشترط Chromium حقيقيًا ويستخدم `chromium_sandbox=True` ونماذج أصلية وCSRF وتفاعل لوحة المفاتيح. يكتب JSON وصور 320/1280 وtrace تحت `.local/qa/functional-completion/scholarly-browser/`، ولا يكتب PASS إلا عند تحقق المسار كاملًا. لا يتجاوز فشل بدء صندوق المتصفح، ولا يستبدله باختبار DOM مصطنع.
