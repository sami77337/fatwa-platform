## Integration contract

Use the **existing** `FATWA_SOURCE_RIGHTS_ENFORCED=True` (literal boolean).
`source_rights.enforcement.required()` is the shared predicate for these consumers.
Literal False/default absent retains historical isolated profiles; malformed values
(None, integers, strings) deny instead of selecting the legacy fallback. The V12
strict composition must explicitly select True. No shared setting, URL dispatcher,
middleware, workflow, or GitHub setting is changed by this lane.

Install the existing citation/source-rights apps, retain the canonical case lock,
scoped identity, maintenance admission and owned synthetic PostgreSQL guards.
`FATWA_SOURCE_RIGHTS_ENABLED=True` and a `SourceRightsAuthority` are still required.
Missing apps/authority, disabled ledger, pending/rejected/expired/revoked rights,
wrong case/edition/digest/version cannot confer source permission. Registration,
import, citation, relation and publication approval remain separate decisions.

- Research policy remains necessary. In strict mode a legacy/custom
  `ResearchRights` policy is additionally intersected with `SourceRightsAdapter`
  for references, editions, knowledge and transcripts. It cannot bypass the ledger.
  Explicit case-media policy remains separate; no READ_MEDIA right is inferred.
- Source read/search and citation display require READ. Citation operations still
  require CITE for each exact current snapshot. The internal locked search helper
  now checks rights by default. The single explicit bootstrap exception is the
  private rights-review service, which requires case scope + SourceRightsAuthority
  VIEW and identity revalidation; it is not a general search or publishing grant.
- Publication REVIEW/APPROVE, library inclusion, anonymous preview and knowledge
  navigation through a published edition require READ + CITE + PREVIEW_METADATA
  for **every** pinned citation. Loss of any required right hides the whole edition,
  including its searchable title/category/body/count, not just the source label.
  Creating/retaining a private editorial candidate is not permission to publish it.
- RELATE loss hides/blocks that relationship while an otherwise permitted
  publication remains available. Private transcript existence is not exposed by
  strict anonymous preview. PreviewPolicy's exact synthetic publication/reference
  grants, expiry and loopback-only boundary are still independently necessary.
- Question, answer, citation and publication rows and their original approvals are
  not deleted or rewritten when rights lapse. Rights are rechecked on current
  access; a new independently approved matching grant can restore availability
  only if all canonical approval/version/withdrawal conditions still hold.
- Private history redacts restricted snapshots and source-bearing editorial or
  correction reasons. Rights-desk correction creates the canonical
  `CitationCorrection` link and a new answer revision, clears answer approval,
  preserves answer text/media, and stores its reason separately from the new
  source's note. It does not silently carry a quote from the old restricted source.
- Apply `knowledge_links.0003_withdraw_unavailable_relation`. Human WITHDRAW remains
  possible after rights lapse, publication withdrawal/supersession or answer
  correction. It still requires scoped identity, KnowledgeAuthority, latest relation
  revision, and append-only action constraints. APPROVE retains the prior current
  publication/answer checks. Migration rollback restores the previous guard.

The internal `_source` and `_citation_snapshots_for_locked_answer` remain integrity
adapters, not access entrypoints. No adapter grants full book text: book 622 is a
TOC for one work, never an invented book body, quotation or global taxonomy.
