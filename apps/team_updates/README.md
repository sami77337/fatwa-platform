## السلوك

- صندوق للأحداث الحالية من نوع INTAKE / FOLLOWUP / SAVE_ANSWER / RETURN_FOR_CHANGES.
  يعرض رقم القضية ونوع التحديث ووقت UTC وإصدارات الوقائع/الجواب فقط؛ لا نسخ لنص
  السؤال أو الجواب أو التعقيب داخل سجل التنبيهات أو القائمة.
- غير المقروء/الكل، مرشح النوع، 20 حدثًا في الصفحة، وعدّادات داخل نطاق الهوية.
- زر صريح لتعليم **حدث واحد** كمقروء. فتح الصندوق أو القضية لا يعلّمه تلقائيًا.
  تعقيب جديد يبقى غير مقروء حتى لو عُلّم تنبيه أقدم من صفحة مفتوحة سابقًا.
- العلامة مستقلة حسب provider + subject + event؛ التكرار مطابق بلا صف إضافي،
  والتنافس بين طلبين ينتج علامة واحدة. الصف يحتفظ بوقت الفعل وauth_epoch.
- علامات القراءة append-only بقيود PostgreSQL. لا تغيير لنسخة القضية أو حالة
  الاستيضاح أو الاعتماد أو سجل الوقائع؛ هذه **ليست** آلية إقرار مراجعة الوقائع
  الواردة في SPEC-U02-010 ولا دليل قراءة السائل.
- الأحداث الأقدم موسومة تاريخية؛ إشعار حفظ المسودة ليس ادعاء جاهزيتها الحالية
  للاعتماد. لا افتراض وجود طلب مراجعة رسمي أو تعيين جديد لا يمثله سجل القضية.

## الصلاحيات والربط

كل القراءة والكتابة تمر بهوية MUFTI الحالية ونطاق القضية وauth_epoch، وبحد القراءة
المقفلة `casework.services._staff_case`. الـPOST لا يقبل دورًا أو هوية من المتصفح؛
إثبات العرض مربوط بسر CSRF والهوية والحدث. إبطال الهوية أو نطاقها يمنع القراءة
والتعليم. أدوار ORGANIZER/ORGANIZER_ADMIN لم تُمنح صلاحية جديدة.

البروفايل المستقل `apps.team_updates.settings` يرث بروفايل casework المحلي المغلق،
ويضيف app واحدًا وROOT_URLCONF فقط. لا تعديل لأي ملف مشترك لدورة الفتوى.

مواضع التكامل الصريحة:

1. إضافة `apps.team_updates.apps.TeamUpdatesConfig` إلى **بروفايل التدريب فقط**،
   وتطبيق migration الخاصة به على قاعدة اصطناعية مملوكة. تنشئ جدول SeenUpdate
   وFK إلى CaseEvent، ولا تعدل جداول casework أو migrations الخاصة بها.
2. `ROOT_URLCONF = "apps.team_updates.urls"` يركّب الصندوق في مسار staff القائم،
   مع الحفاظ على حواجز المسار والدخول وCSRF وcookies وno-store وloopback.
3. عمليات القضية مثل open/draft/clarify تُفوّض إلى الواجهة الأصلية دون نسخها.
   عند تركيب #212، يضبط مسؤول التكامل `FATWA_TEAM_UPDATES_CASE_VIEW` إلى callable
   `apps.team_workspace.views.workspace`. الإعداد خادمي؛ لا يختاره المتصفح.
4. الواجهة الداخلية `_staff_case` اعتماد صريح قابل للترقية إلى public read API
   لدى مسؤول دورة الفتوى؛ لم نغيّرها أو ننسخ تحققها.

الرجوع عن migration يحذف علامات القراءة الجديدة فقط، مع بقاء أحداث القضايا
وأجوبتها. لا ندّعي حفظ علامات القراءة عند إزالة التطبيق. لا ترحيلات إنتاجية.

## التحقق المركّز

```sh
python infra/dev/with_casework_postgres.py --pg-bin /path/to/postgresql/17/bin --major 17 --settings apps.team_updates.test_settings -- python manage.py test apps.team_updates.tests --noinput
FATWA_FASTBUILD_BROWSER=/usr/bin/google-chrome python infra/dev/with_casework_postgres.py --pg-bin /path/to/postgresql/17/bin --major 17 --settings apps.team_updates.test_settings -- python manage.py test apps.team_updates.browser_tests --noinput
ruff check apps/team_updates
```

اختبارات مستقلة للهوية والنطاق وإبطال الصلاحيات وCSRF والنماذج المزورة، والتعقيب
المتزامن مع قراءة تنبيه أقدم، والتنافس، وثبات القضية، وتصفية الصفحات وimmutability.
تعاد أيضًا عقود HTTP الأربعة عشر القائمة ضد نقطة الربط الاختيارية.
فحص المتصفح يغطي تعليم التنبيه ثم وصول تعقيب وتصفية الكل وفتح القضية دون
تعليم ضمني، عند 320 و1280 بكسل. دليل المتصفح في `.local/qa/team-updates/browser`.

نتيجة محلية: 24/24 اختبار قاعدة/HTTP على PostgreSQL 17.11، واختبار Chromium
واحد ناجح (154.0.8037.57)، دون تجاوز أفقي أو طلبات خارجية أو أخطاء صفحة.
نجح Ruff وفحص عدم اختلاف migrations. المتصفح المحلي يعمل بـwrapper خارج
المستودع بلا browser sandbox لقيد الحاوية؛ فحص CI يحتفظ بالـsandbox ويشغّل
PostgreSQL 17/18. نتائج CI تُبلّغ على رأس الالتزام المنشور، ولا تُفترض مسبقًا.

حدود التغطية: لا إشعارات خارجية (SPEC-U02-036)، لا scheduler أو إرسال، لا إدارة
تعيينات، لا إعلام عن أحداث لا تُحفظ حاليًا، ولا نظام صلاحيات جديد. المطابقة مع
SPEC-U02-035 جزئية وليست قبولًا كاملًا للوحدة.

**NOT_DEPLOYED / GATES_HOLD / ACCEPTANCE_HOLD.** بيانات اصطناعية فقط، لا دمج main،
ولا نشر أو إرسال فعلي.

## تصنيف مصادر التنبيه الحالي

عند تطبيق سجل الخصوصية، يحتفظ تنبيه الجواب بتصنيف إصدار `ANSWER` الفعلي،
ويحتفظ تنبيه التعقيب بتصنيف مرفقه أو تفريغه أو إيصال مصدره الأصلي. يُستبعد
التنبيه غير المسموح قبل تكوين القائمة والعدّادات. إثبات عرض قديم لا يتيح
تعليمه كمقروء بعد سحب الإذن؛ لا تُنشأ علامة قراءة عند الرفض.

تظل حراسة التصنيف سارية حتى آخر تحقق للهوية والمصدر، فتتراجع الكتابة إذا
تغير الإذن أثناء العملية. لم يُنشأ تصنيف عالمي جديد للأحداث ولم تُمنح
صلاحيات إضافية للفريق. اختبارات الربط: `apps.team_updates.privacy_tests`،
وتغطي المصدر الأصلي للجواب والمرفق وسحب الإذن وثبات علامات القراءة عند الرفض.
