# Versioned allowed-material Developer API

Candidate original370 / SPEC-U13-022 / D-057. This unit adds a real read-only developer contract over the current typed material library; the inherited fiqh TOC endpoint is not recounted. Default flag `FATWA_MATERIAL_API_ENABLED=False`. It remains inside the established loopback-only synthetic development composition. No production exposure, service-account security acceptance or official dataset release is claimed.

The native materials index links to a developer explorer. It executes bounded Arabic metadata search through actual GET forms, opens exact versioned JSON and downloads actual original bytes. `/library-preview/api/v1/materials/schema.json` describes the implemented version1 contract. The API accepts GET/HEAD only and uniformly rejects unsupported methods, duplicate/unknown parameters, private identifiers and unbounded pagination.

The list contains the latest currently released version per public material, filtered before pagination totals. Exact historical version URLs never silently redirect or substitute a newer version. Results carry stable public material IDs, immutable version numbers/digests and readable work/edition/creator/locator references. An explicit field allowlist omits private case/source/internal-version IDs, storage keys, original filenames, actor history and rights notes. All responses are private/no-store; HEAD still performs current authorization without sending a body.

Metadata permission does not reveal text or file content. Original download needs both current PUBLIC_CONTENT and DOWNLOAD uses. Every response remains inside the canonical material projection until serialization and all actual storage reads/permission callbacks finish; final pure identity and configuration checks reject late revocation. Missing files, authorities, identities, withdrawn or expired exact releases fail closed. Privileged write/approve/publish/import and private-case operations have no API route, and no integration credential is invented or exposed.
